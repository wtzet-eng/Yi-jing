## Offline behavior

`npm run build` now generates a versioned service worker containing every built local asset, including the bundled hexagram data, JavaScript, CSS, icons, manifest and privacy page. Installation fails as a whole if a required file cannot download. The old app remains available after a failed update. Pages and their scripts come from one build, avoiding mixed cached versions. API requests and external videos are not cached. Only Yijing-owned caches are cleaned.

The page reports “Ready for offline use” after the active worker verifies the complete cache. A new version waits until all app windows close or the user chooses the update/reload button. Casting, readings and simple presence prompts work locally. AI replies and YouTube videos require internet; a 12-second request timeout prevents a stalled connection from blocking basic practice indefinitely.

Installation guidance distinguishes supported desktop browsers from Firefox on Linux. Offline website use does not require a desktop installation. Initial download requires internet; browser storage clearing/eviction removes offline files, requiring another online visit. AI is not downloaded to the device.

## Deployment

Deploy using `npm ci` and **`npm run build`**, then serve `dist` (or `NODE_ENV=production npm start`). Running only `vite build` will not generate the offline asset list. After deployment, existing users should open online, accept the update or close all app windows and reopen, and wait for “Ready for offline use” before disconnecting. Check airplane-mode reopening on the actual target phone/desktop before announcing full device validation.
